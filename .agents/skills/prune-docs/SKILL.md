# 精简 plan/progress 文档（prune-docs）

z.plan.md 附录越积越多、x.progress.md 已完成区越来越长 → 压缩精简。只写文档，不修改业务代码。

> 本文件为项目自建 skill 权威源（`.opencode/skills/` 同名旧版为历史副本）。依据：文档在 git 版本控制中，历史可回溯，可大胆压缩（原始过程记录不保留）。

## 执行标准（双压缩模板）

### 模板一：z.plan.md 附录压缩（PL / A 两类附录同构）

```
## 附录 PL{NNN}：{标题}（{日期} 立项）

> 状态：✅ 已完成（{日期} 收口，{验收一句话}）。任务组见 x.progress.md「PL{NNN}」。

**定案口径（收口浓缩）**

- {方向决策逐条浓缩：决策 + 一句依据}
- {实施要点浓缩：编号范围 + 关键实现定案（含中途翻案/用户拍板的变更，注明"以本附录为权威定案"）}
- {验收浓缩：探针/截图/回归结论}

**明确不做**：{边界排除，保留}
**遗留**：{无阻塞项 / 遗留项列表}
```

审计附录（A{NNN}）压缩模板：

```
## 附录 A{NNN}：全量代码审计报告（第N轮，{日期}）

> 范围：{范围概述}；{方式概述}
> 结果：**P 级 {N} 条（{严重度分布}）/ 参考级观察项 {N} 条（用户复核{结论}）**
> 状态：✅ 已修复（{日期}：FIX{NNN} 共 {N} 项全部落地；探针回归全过；任务清单见 x.progress.md）

- **上轮复核（FIX{上轮} {N} 项）**：{在位/回退/漏改结论}
- **P0-P3（{N} 条）**：{按严重度浓缩逐条：位置 + 问题一句话 + 修复结论}
- **参考级观察项 {N} 条**（用户复核{结论}）：{浓缩列表}
- **亮点**：{浓缩}
```

### 模板二：x.progress.md 已完成组压缩

```
### PL{NNN}: {标题} [来源引用] ✅

> 结果：{一句话结论 + 验收概览}。全组 {N} 条勾结。详见 z.plan.md 附录 PL{NNN}。

- [x] PL{NNN}.{序号} {标题} —— {做法浓缩一句话}；验证：{方式}（{日期} 已验证：{一句话结论}）
```

- 优先压缩粒度 = **组级摘要化**（保留组标题 + 结果行，条目合并为少数几条浓缩行）；条目级压缩仅在组极长时使用
- 历史字母系列（A–H）压缩保持其既有记录形态（`## 第 N 轮审计整改完成（X 系列…）` 标题 + 浓缩段），编号与轮次语义不动

### 公共规则

1. **权威源声明**：压缩后标注机制行（照既有措辞）：`> 历史归档：{原位置}为历史记录保留；{新清单}为唯一权威源，已定案项后续不再重复报告`
2. **防重复记账**：✅ 条目提炼为"问题名（修复编号）"并入 z.plan.md「观察项豁免定案清单·已修复记账」小节（防止后续审计把已修复问题当新问题重复报告）
3. **未完成区不可碰**：`## 未完成` 区所有 `- [ ]` 条目一律不可压缩/删除/改写

## 执行流程

### Step 1：分析现状

- 统计 z.plan.md 附录（PL/A 两类）与 x.progress.md 已完成区各组的条数/行数
- 识别可压缩对象（已完成组、已收口附录）与不可动对象（未完成条目、豁免定案清单权威源、版本三方一致锚点）

### Step 2：询问环节（必做）

1. **压缩范围**：哪些附录/任务组
2. **压缩方式**：组级摘要化 vs 条目级浓缩 vs 直接删除（仅限纯过程记录）
3. **防重复记账**：是否执行（默认是）

### Step 3：执行

- 只动 z.plan.md / x.progress.md
- z.plan 附录：按模板一压缩（保留标题、状态行、定案口径/四节浓缩、明确不做、遗留）
- x.progress 已完成组：按模板二压缩（保留组标题 + 结果行 + 浓缩条目）
- **保留**：编号、版本号、完成日期、结论语义（✅ 状态）、机制性结论（翻案定案/防漏损升级等）、交叉引用（[audit#A{NNN}] 等来源引用）
- **删除**：过程细节、验证步骤原文、逐条长表

### Step 4：汇报

- 压缩前后行数对比表
- 提醒 git commit（文档变更由用户提交）

## 硬性约束

- **未完成条目（`- [ ]`）一律不可压缩/删除/改写**
- 编号与交叉引用不可断裂（附录标题保留原文编号；任务组保留组号与来源引用）
- 版本三方一致锚点（base.json / README 徽章 / 最近 commit）不在压缩范围
- 防重复记账必做
- 不修改业务代码、不删探针
- 不擅自执行 git 写操作（提交由用户执行）
