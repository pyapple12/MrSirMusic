# 按 x.progress.md 章节执行任务（progress-task）

用户指定 x.progress.md 中的一个任务章节（标题/编号由用户输入），按固定流程执行。

> 本文件为项目自建 skill 权威源（`.opencode/skills/` 同名旧版为历史副本）。

## 触发场景

用户消息形如：

- "研究 x.progress.md 中 PL001.3 deck_view 布局重构"
- "按 x.progress.md 中 X 章节执行"
- "推进任务 ### PL001"
- "推进任务 FIX001"

章节编号（如 PL001.3、FIX001.2、PATCH001.1）是用户对任务的标识。指定任务组（如 PL001）时覆盖该组全部子任务；指定子任务时只执行该条。历史字母系列（A–H）条目同样适用本流程（编号即标识）。

## 执行流程（MM 2026-11-05）

> 工具无关约定：本 skill 只描述**能力**，不绑定具体 harness 的工具名——环境有同名工具（如 `edit`）就直接用，没有就用等价通用手段，**不得因工具名不同而跳过步骤**。

### Step 1：研究

- 通读用户指定的 x.progress.md 章节，确认：任务范围、做法说明（`—— 做法` 为执行要点）、验证方式
- 必要时读相关代码上下文（只读）

### Step 2：形成自己的 todo list

- 建立并维护一份细分任务清单：标注优先级（high/medium）、覆盖该章节所有子任务
- 环境有 todo/清单类工具就用工具；没有就在回复里以编号清单列出并逐条跟踪状态——两者等价，不得因无工具而跳过本步
- 执行中持续更新：完成即勾、拆分即补；收尾时清单状态与 x.progress 勾选一致

### Step 3：形成检验方案

- 每个任务明确"完成后的检验标准"：可执行、可断言
- TDD 风格：行为修复类先写探针（`.temp/` 下 probe 脚本），修复前跑应 FAIL（复现问题/证明探针有效），修复后跑 PASS（**红灯 → 绿灯证据要留存**）
- 包含回归验证（全量 14 探针 offscreen 重跑）+ 冒烟（AGENTS"运行与验证"import 命令）
- 视觉类任务检验 = `.temp/ui_review_shots.py` 重拍 + 多模态读图核对（对照条目中写明的截图读图点）

### Step 4：执行任务

- 逐项实现，遵守 AGENTS.md 规范（参数走 `config/static/*.json`、函数下 `#` 中文注释、文件尾 `# =====` 说明区、类型注解、pathlib 强制、import 三段顺序、事件契约改动走 events.py → event_bus → bridge 三处）
- **分层红线**：modules/ 零 UI 依赖（禁止 import PySide6；engine 内部 QtMultimedia 延迟导入为唯一特许）；ui/ 是唯一 Qt 层；ui/themes 与 ui/sounds 之外不得新增 QtMultimedia/Qt 网络依赖面
- **容错登记制**：新增任何降级/容错点必须先登记 AGENTS「错误策略·容错登记制」（场景/降级行为/理由三要素）
- **正式注释禁止 `.reference/` 标注**；参考来源写 w.study.md
- 修改既有文件用 edit 工具精确替换；临时脚本/文件一律 `.temp/`
- 每项完成后立即跑对应检验；**编辑后门禁**：`.py` 改动 → 冒烟 import；`.md`/`.json` 改动 → 涉及配置时重跑 a1 探针

### Step 5：用检验方案验证

- 跑检验脚本确认 PASS；全量回归（14 探针，命令见 AGENTS"运行与验证"）+ 冒烟 + `python main.py --version`
- **修复验收（每批强制，防"修复引入新缺陷"）**：每批完成后、全量回归前，逐项对照原问题做**反向验证**（原问题是"红占位图"→验收"中心像素非红且尺寸正确"；原问题是"按钮巨条"→验收"宽度 ≤96px"），验收记录落 `.temp/verify_{批次}.py` 或截图
- **验证样例独立化**：探针结构性样例必须来自真实数据快照或独立证据，禁止手写与实现同源的 mock 自证；播放链探针必须用 `wave` 模块生成真实 PCM 音频（假 RIFF 头文件会解码失败连锁失真——AGENTS 环境陷阱）
- 确认正确后才认为完成

### Step 6：确认完成与汇报

- 勾选 x.progress.md 对应条目（句尾追加 `（YYYY-MM-DD 已验证：{一句话结论}）`；**TDD 类条目须带红灯 → 绿灯证据**）
- 汇报：检验方案结果表 + 修改文件清单

## 多模态节点

任务涉及读图（截图核对、封面/效果核对、UI 评审）时：

- 当前模型无视觉能力（读图工具返回 `Cannot read: this model does not support image input`）→ **停下，通知用户切换多模态模型**后再继续
- 未实际读到图时严禁声称"能读到"或编造图片内容；图读失败如实报告
- offscreen 截图中文呈 □ 占位——文字排版类核对必须真机截图（AGENTS 环境陷阱）

## 硬性约束

- 检验方案**先于**实现（TDD：先 FAIL 后 PASS）
- **未验证不算完成**——确认正确后才勾选
- 不擅自执行 git 写操作；**用户明确要求提交/推送时按其指示执行**（提交前仍须 `git status` + `git diff`（含 `--stat`）核对改动范围并草拟内容交用户确认）
- 不擅自做章节范围外的操作（如改版本号、改配置——版本推进仅在收口条目内执行）
- live 验证禁止更改电脑系统设置（主题/DPI/动画效果）
